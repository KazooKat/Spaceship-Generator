# Troubleshooting

Quick reference for common errors when running the spaceship generator. Companion to [quickstart.md](quickstart.md) — if a command in the quickstart fails, check the table below first.

## Common errors

| Symptom | Cause | Fix |
|---|---|---|
| `Palette 'NAME' not found at .../palettes/NAME.yaml` | The palette name passed to `--palette` does not match any YAML in `palettes/`. | Run `spaceship-generator --list-palettes` to print every available name (or browse [palettes.md](palettes.md)), then re-run with one of those. |
| `argument --hull-style: invalid choice: 'X'` (or `--engine-style` / `--wing-style` / `--cockpit`) | The shape-style value is not a member of the corresponding enum. | Run `spaceship-generator --list-shape-styles` to see every `HullStyle` / `EngineStyle` / `WingStyle` member. |
| `argument --greeble-style: invalid choice: 'X'` | The greeble type is not a `GreebleType` enum member. | Run `spaceship-generator --list-greeble-types` for the bare value list. |
| `argument --weapon-type: invalid choice: 'X'` (or unknown values warned by `--weapon-types`) | The weapon-type token is not a `WeaponType` enum member. | Run `spaceship-generator --list-weapon-types` for the bare value list. |
| `--no-weapons and --weapon-count are mutually exclusive` | Both flags were passed in one invocation. | Drop one — `--no-weapons` is the shortcut for `--weapon-count 0`. |
| `--no-greebles and --greeble-density are mutually exclusive` | Both flags were passed in one invocation. | Drop one — `--no-greebles` is the shortcut for `--greeble-density 0`. |
| `--stats and --stats-json are mutually exclusive` | Both stat flags were passed. | Drop one — `--stats-json` is the machine-readable variant of `--stats`. |
| `--output - is single-ship only; mutually exclusive with --repeat, --fleet-count, --seeds` | Stdout-streaming mode only supports one ship per invocation. | Drop the bulk-mode flag, or write to a directory with `--out PATH` instead of `--output -`. |
| `--ship-size: W>=4, H>=4, L>=8 required` | Dimensions below the `ShapeParams` floor. | Pass dimensions that meet the minimums (e.g. `--ship-size 8x6x16`). |
| `argument --greeble-density: must be in [0.0, 1.0]` | Greeble density is a unit float. | Pass a value in `[0.0, 1.0]`. |
| `--seeds range must be 'A-B' with integers` (or `must not be empty`) | Malformed `--seeds` value — accepts comma-list, inclusive range, or mix. | Use `--seeds 1,2,3`, `--seeds 0-9`, or `--seeds 1,3-4,9`. |
| Web UI returns HTTP 429 with `{"error": "rate_limited"}` | Per-IP fixed-window rate limit was hit on a `POST /generate` / `/api/generate` / `/api/batch` / `GET /preview-lite` / `/download-fleet` request. | Wait `Retry-After` seconds, or tune via env vars `SHIPFORGE_RATE_LIMIT` (default 30) and `SHIPFORGE_RATE_WINDOW` (default 60s) — see [web_ui.md](web_ui.md). |
| `ModuleNotFoundError: No module named 'flask'` (or `jsonschema`, `PIL` / `Pillow`) | Optional dependency not installed in the active environment. | `pip install -e .[dev]` to pick up the dev extras, or install just the missing package (e.g. `pip install flask`); `jsonschema>=4.0` is also pinned in `requirements-dev.txt`. |
| `presets unavailable` / `weapon_styles unavailable` warning on stderr | Optional submodule failed to import (partial install or in-progress refactor). | Re-install the package with `pip install -e .` from the repo root; the CLI still runs without these but `--preset` / `--weapon-*` flags will no-op. |
| `unrecognized arguments: --list-engine-styles` (or any of the per-component `--list-*-styles[-json]` flags) | The per-component list flags (`--list-hull-styles`, `--list-engine-styles`, `--list-wing-styles`, plus their `-json` siblings, and `--version-json`) shipped in cycle 2 of 2026-05-07 — older installs only expose the bundled `--list-shape-styles[-json]`. | Run `spaceship-generator --version` (or `--version-json` for tooling) to see the installed version; if it predates the cycle-2 release, `pip install -e .` from the repo root or upgrade the package. See [cli.md](cli.md) for the full sibling pack. |
| `bench_*.py --csv` output is empty (or interleaved with banner text) when piping | The `--csv` mode splits streams: CSV goes to **stdout**, the run-banner + per-iter progress lines go to **stderr** (see [bench.md](bench.md)). Folding stderr into stdout (`2>&1`) corrupts the CSV document. | Drop the `2>&1`: `python scripts/bench_summary.py --csv > out.csv` is correct, `python scripts/bench_summary.py --csv > out.csv 2>&1` is wrong. To capture both streams separately, use `... --csv > out.csv 2> out.log`. |
| `palette_stats.py` reports fewer palettes than `ls palettes/` shows | `scripts/palette_stats.py` reuses the strict palette loader; palettes that fail to parse are silently dropped from the corpus stats so a single broken file doesn't poison the aggregate. | Run `python scripts/palette_lint.py --all --strict` to surface the offenders — every dropped palette will appear with one or more `error:` / `warn:` lines pointing at the offending YAML. |
| `GET /api/version` returns `{"version": "0.0.0+unknown"}` | The route uses `importlib.metadata.version("spaceship-generator")`, which returns the editable-install fallback when the package was installed with `pip install -e .` in some environments (no installed `.dist-info`). | Re-install non-editable (`pip install .`) for a release-tagged build, wait for the next release tag, or read `__version__` from the package directly (`python -c "import spaceship_generator; print(spaceship_generator.__version__)"`). See [web_ui.md](web_ui.md) for the route. |
| `palette_diff.py` shows `<missing>` for a role | The role is defined in only one of the two palettes; `scripts/palette_diff.py` treats absent roles as gaps rather than errors, since palettes legitimately diverge on optional roles. | To see which roles are MANDATORY (and would therefore be a real defect when missing) run `python scripts/palette_lint.py --strict` against each palette — strict mode surfaces every missing required role. |
| Cross-axis property test fails with one specific `(style_a, style_b, seed)` tuple | One member-pair × seed combination in a `tests/test_properties.py::test_property_*_cross_*` parametrize grid hit a regression — the failure node ID self-names the offending tuple. | Reproduce with `pytest tests/test_properties.py -k "<test_name> and <style_a>-<style_b>-<seed>"`, then inspect the resulting `.litematic` size / contents (the test writes to `tmp_path` — print it from the test, or re-run the same `generate()` call locally with the same seed). |
| `palette_search.py --block <id>` prints "0 hit(s)" and exits 1 | The `--block` value did not match any palette role in `palettes/`. Two common causes: (a) the bare block id was passed without the `minecraft:` namespace prefix, which never matches because the corpus stores every block as a fully-qualified `namespace:id` string; (b) the block really is unused — `palette_search.py` deliberately exits 1 on no-hits so CI / shell pipelines can branch on `$?` (exit 0 = at least one hit, exit 1 = no hits / missing `palettes/`, exit 2 = bad CLI args). | Re-run with the full id (`python scripts/palette_search.py --block minecraft:stone`, not `--block stone`); blockstate suffixes (`[axis=y]`) are stripped before comparison so `minecraft:oak_log` matches `minecraft:oak_log[axis=y]` too. If the exit-1 is intentional in CI, treat it as a "no callers" signal rather than a failure. |
| `palette_search.py --block <id>` prints dozens / hundreds of hits | The block is a *common* role across the corpus (e.g. `minecraft:stone`, `minecraft:white_concrete` typically appear in 20+ palettes). The fixed-width text table is hard to scan at that size. | Re-run with `--csv` to get a parseable `palette,role` stream you can pipe into `sort` / `uniq -c -f1` / a spreadsheet (`python scripts/palette_search.py --block minecraft:stone --csv > hits.csv`); banner lines route to stderr in `--csv` mode so stdout stays clean. If you want palettes that use the block in a *specific* role only, filter the CSV on column 2 (e.g. `awk -F, '$2=="HULL"' hits.csv`). |
| Can't find the per-`StructureStyle` override list (engine count, wing prob, hull rx/ry, etc.) in `docs/architecture.md` | The architecture doc's `## Structure pipeline` section names the dispatch functions but doesn't enumerate every per-style numeric override (those are intentionally kept in the source so the doc can't drift). | Read `src/spaceship_generator/structure_styles.py` directly — the per-style `if style == StructureStyle.<X>: return ...` branches in `profile_fn` / `hull_rx_ry_scale` / `engine_count_override` / `engine_radius_scale` / `wing_prob_override` / `wing_size_scale` are the truth source. See [architecture.md#structure-pipeline](architecture.md#structure-pipeline) for the seam diagram. |
| Fleet `.litematic` files from one run overwrite files from a previous run in the same `--out` directory | `--fleet-count N` writes per-ship files as `ship_<seed>_<idx>.litematic` into `--out` (default `out/`). Re-running with the same `--seed` (or picking the same fleet seed at random) into the same `--out` regenerates the same filenames, so the old `.litematic` files are silently overwritten. | Either pass a different `--out` directory per fleet run (`--out fleets/run-2026-05-08/`), pass an explicit `--seed` you don't reuse, or move/rename the previous run's files before re-invoking. Fleet runs only collide *with each other*; the per-ship `_<idx>` suffix prevents within-fleet collisions. |
| Authoring a new palette and a YAML edit causes a silent failure (missing role, bad block id, role typo, indent error) | The runtime palette loader is tolerant — many authoring mistakes don't surface until generate-time as silent no-op blocks or missing-block errors at Litematica load. | See [palette_authoring.md#common-pitfalls](palette_authoring.md#common-pitfalls) for the five mistakes new authors hit most often, and run `python scripts/palette_lint.py --strict <palette.yaml>` (or `--all --strict` for the whole `palettes/` corpus) — that's the canonical "catches this" tool for everything in that pitfalls list. |
